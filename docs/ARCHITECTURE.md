# 技术架构

## 数据与证据

MemPrism 保存原始消息，并建立可回到原文的片段和证据目录。片段记录来源 ID、范围、版本及哈希；派生索引负责召回，保存的原始内容负责提供证据。返回前检查用户范围、来源有效性与可见状态。

`app/ingest.py` 协调 Add；`app/store.py` 负责持久化；`app/segments.py` 定义片段与索引核验；`app/evidence_catalog.py` 建立确定性证据目录。实现中的可选抽取、图候选、类型视图等研究模块，不代表本次配置实际启用。

## 写入路径

1. 校验协议与请求身份，协调相同请求的重复执行。
2. 在用户范围内准备所需表示，分批请求文档 Embedding。
3. 在受控事务中保存原文、派生表示、索引与发布状态，检查租约 fencing。
4. 完成所需发布与回执后才确认成功。

正式运行曾出现写门禁、续租、全历史核验成本等问题，后续运行快照包含对应修订。请求幂等不能保证外部供应商只计费一次：外部调用成功但本地发布未完成时，重试可能再次产生供应商费用。

## 检索路径

`app/retrieval.py` 执行用户内词面与精确向量检索、RRF 融合、证据组装和输出预算。`app/exact_dense.py` 仍是精确候选评分，不能以名称中的加速推断使用了 ANN。长问题分成有界的 UTF-8 窗口，再聚合查询向量；窗口大小和总输入预算是不同约束。

`app/evidence_architecture.py` 将来源目录、历史导航和支持组接入候选组织。它可以保留表头与行、规则与引用等显式依赖，提供有限的状态、历史和披露标记。敏感主题匹配只缩小既有用户范围内的返回内容，不能授予新访问权限。这些规则不构成通用的语义推理或隐私保证。

输出最多 100 项，并受字符和 tokenizer 预算限制。证据服务返回保存的来源内容及确定性来源标签，最终答案和判分由下游系统完成。

## 并发与核验

SQLite/WAL 允许读快照与写事务分离；进程内写门禁、任务租约、回执和发布元数据约束并发行为。`app/read_pool.py`、`app/read_readiness.py`、`app/write_runtime.py`、`app/writer_gate.py` 负责连接、读写协调与核验复用。

复用的是特定数据库身份、连接版本和发布快照对应的核验结果；不是按时间盲目认定旧数据仍然正确，也不缓存用户查询答案。`app/vector_checks.py` 与 `app/vector_json.py` 保留向量内容校验；`app/embedding_http_pool.py` 复用有界 HTTP 连接，同时保持各请求的认证和 Cookie 状态分离。

`deploy.serving_factory_093.py` 的健康接口核对服务控制元数据；Add/Search 仍保留各自需要的来源和数据检查。健康成功不等同于对全库、供应商额度、Full 容量的重新认证。

## 复杂度与性能边界

设当前用户有 N 个有效候选向量、向量维度为 d、融合后候选上限为 K。

| 环节 | 主要成本 |
|---|---|
| FTS5 | 取决于查询词的倒排命中和排序，不可一概视为常数 |
| 精确 Dense | 主评分需随 N × d 增长；另含读取、解码、验证和选择成本 |
| RRF | 受输入候选数量和排序成本约束；当前候选预算有界 |
| 证据组装 | 候选及支持组有界，但历史目录查询、来源核验仍有数据相关成本 |
| 写入 | 文档长度、片段数、Embedding 批次与事务竞争共同影响延迟 |

不将候选上限 200 解释为底层 Dense 只扫描 200 条向量。当前没有证明生产端到端五倍加速；早期合成实验和短时自然流量只能支持其对应范围内的结论。

## 部署拓扑

完成评测时采用云端 HTTPS/Nginx 入口、反向 SSH 通道、本机恢复网关和本机单 worker 引擎。引擎修订为 local-103；通道守护修订为 gateway-105。公网域名的证书和入口仍在云端，本机不需要开放公网入站端口。

`operations/reference/` 保存运行时使用的网关、TLS 上下文和 watchdog 组件，按原字节发布。它们需要部署方提供业务进程就绪检查、同库身份、凭据输入和通道编排；并非可以直接接管其他机器的完整迁移工具。

网关只在满足原进程退出、替代进程身份及数据库一致、服务重新就绪等条件后执行有限传输恢复。业务 HTTP 422/429/503 不由网关伪造成成功。TLS 保持证书和主机名验证；watchdog 只对其自身子进程的指定原生退出码做有上限的恢复。

## 已知边界

- 正式 Full 完成不等于不存在长期运行故障；先前原生进程崩溃的最终底层原因没有全部证实。
- SQLite 仍有单写者约束；更多线程或更高并发上限不保证吞吐同比增长。
- 精确向量扫描与用户历史规模相关，大规模部署需实测冷读、内存和锁竞争。
- 规则、状态和披露识别依赖可观察的文本形式，不能代替完整语义理解。
- 未实现自动数据到期清理。部署方应按赛事或产品约定处理原始库、WAL、备份及其他副本。
